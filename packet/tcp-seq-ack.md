# 实验：读懂 SEQ 与 ACK 的推进

对应实验：`tcp/echo`。不需要新代码——就用握手实验的抓包结果，把从建连到关闭的整条时间轴拉出来看序号如何流动。

## 运行与抓包

```bash
sudo tcpdump -i lo0 -nn port 9000
# 终端 2: go run ./tcp/echo/server
# 终端 3: go run ./tcp/echo/client
```

Wireshark 同样过滤 `tcp.port == 9000`，用相对序号视图最直观。

## 你应该看到什么（Wireshark 相对序号）

客户端发送 `hello, tcp (t=12:00:00.000)\n` 共 28 字节，完整时间轴：

```text
No.  Info                            Seq   Ack   Len   说明
1    64631 → 9000  SYN               0     -     0     客户端 ISN（相对化为 0）
2    9000 → 64631  SYN, ACK          0     1     0     服务端 ISN=0；确认客户端下一个字节是 1
3    64631 → 9000  ACK               1     1     0     确认服务端下一个字节是 1；握手完成
4    64631 → 9000  ACK (PSH)         1     1     28    数据！seq=1 起的 28 个字节
5    9000 → 64631  ACK (PSH)         1     29    28    服务端回显 28 字节，并捎带确认 ack=29
6    64631 → 9000  ACK               29    29    0     确认收到回显
7    64631 → 9000  FIN, ACK         29     29    0     FIN 占 1 个序号
8    9000 → 64631  ACK               -     30    0     确认 FIN：ack = 29+1
9    9000 → 64631  FIN, ACK         29     30    0
10   64631 → 9000  ACK               -     31    0     ack = 29+1 (FIN) ... 服务端 seq 到 30，ack=31
```

## 读法：两条铁律

```text
SEQ     = 这段数据从字节流的哪里开始（本报文第一个字节的流内偏移）
ACK(n)  = 序号 n 之前的字节我全部收到了，请从 n 开始继续发
```

对照上表验证：

- 报文 4：客户端发了 28 字节，`Seq=1`（SYN 占走 0）、`Len=28`，所以这 28 字节覆盖流内 `[1, 29)`。
- 报文 5：服务端的 `Ack=29` = 1+28，精确等于"已收到的字节数 + 1"。**ACK 每次推进的量 = 新收到的字节数**。
- 报文 7：FIN 占一个序号，所以它的 `Seq=29`（接着最后的数据字节），而报文 8 的 ack 推进到 30。
- 报文 5 是 **ACK 捎带（piggyback）**：服务端读数据后马上回显，回复数据的报文顺便携带了对请求的确认，不需要单独的纯 ACK。这是"双向数据同时流动时 ACK 搭车"的典型形态。

> 本地回环抓包时丢包/重排几乎不会发生；在有损网络中重复执行，你会看到同样的 Seq/Len 但 Ack 不再前进的报文（重复 ACK），连续 3 个重复 ACK 触发发送端快速重传。机制本身与上表完全一致。

## 这如何解释"可靠、有序"

- **有序**：接收方按 Seq 把乱序到达的段重排后再交给应用。应用看到的永远是完整有序的字节流。
- **可靠**：发送方发出 `Seq=1, Len=28` 后必须等到 `Ack=29`；等不到（超时或收到重复 ACK）就重传。重传由内核负责，`conn.Write` 感知不到。
- **累计确认**：`Ack=29` 不需要为每一段单独回执，它一句话确认了之前所有字节。代价是"第 5 字节丢了，第 6~28 字节到了也只能反复确认 5"——这正是快速重传的触发条件。

## 与 Go 代码的关系

- `conn.Write(p)` 返回"已拷贝进内核发送缓冲区的字节数"，**不等于**"对方已确认"。确认与否由内核的重传机制兜底。
- `conn.Read(buf)` 返回的 n 是"当前缓冲区里可读的字节数"，与对方 Write 的边界无关（字节流实验专门演示这一点）。
- 整套 SEQ/ACK/重传/排序对应用完全透明——这就是"传输层由操作系统替你实现"的具体含义。
